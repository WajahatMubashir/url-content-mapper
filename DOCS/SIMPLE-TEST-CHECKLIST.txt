================================================================================
                           WHAT SHOULD YOU SEE?
================================================================================

BEFORE THE FIX (v1.2):
  Console: window.dataLayer
  Result:  [] or GA4 events without content_category

  → GA4 fires BEFORE content_category is set
  → Results in "(not set)" in reports


AFTER THE FIX (v1.3):
  Console: window.dataLayer
  Result:  [{content_category: "homepage"}, ...GA4 events...]

  → content_category set FIRST
  → GA4 page_view event includes it
  → Reports show correct categories


================================================================================
                          VISUAL EXAMPLE
================================================================================

When you type "window.dataLayer" in Console, you should see:

Array(3) [
  0: {content_category: "homepage"}              ← THIS IS WHAT YOU WANT TO SEE
  1: {event: "gtm.js", gtm.start: 1234567890}
  2: {event: "page_view", ...}
]

The content_category should be in position [0] or very early in the array,
BEFORE the page_view event.


================================================================================
                        TROUBLESHOOTING
================================================================================

ISSUE: Version still shows 1.2

ISSUE: Console shows [] (empty array)
FIX:   Clear all caches. Test in incognito mode.

ISSUE: Console shows errors
FIX:   Check TESTING-GUIDE.md for specific error solutions.

ISSUE: content_category not visible
FIX:   1. View page source
       2. Search for "urlcoma-frontend-script"
       3. Verify inline script is there
       4. Check for caching issues
